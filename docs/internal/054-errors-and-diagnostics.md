**Four independent questions:** did this requested canonical transition definitely not commit; was its commit acknowledged; is that acknowledgement unknown; and is the physical effect unknown? A `not_committed` outcome after dispatch can coexist with an already executed effect. An acknowledged uncertainty record can coexist with unknown external execution. Neither the exception's class nor a wire `rejected` label bridges this gap.

`platform/reconciliation.js#reconcileTask` requires current `expectedRevision`, eligible unknown operation/task, a live human principal, current admission authority and decision-matching evidence: `confirmed_completed`→`receipt`; `confirmed_not_executed`→`no_effect_confirmation`; `authorized_compensated`→`compensation_receipt`; `still_unknown`→`operator_review`. `INSUFFICIENT_EVIDENCE`, `PRINCIPAL_INVALID`, `STALE_REVISION`, `INVALID_TRANSITION`, and `RECONCILIATION_REQUIRED` are not automatic recovery instructions. Re-admission requires the explicit recorded `not_executed` reconciliation; compensation is not physical rollback.

### Trusted raw causes versus untrusted wire/canonical data

`interop/adapter-protocol.js#adapterError` intentionally preserves a host-side `cause` when the trusted bridge wraps a local transport/validation failure. Treat the Error object/stack/cause as privileged diagnostics, not a serialization envelope. Adapter server error frames contain only bounded identity fields, normalized code and classification—no exception `message`, stack or cause. The protocol permits provider-selected bounded code identifiers; providers must not encode secrets in identifiers/codes. These are compatibility/error data, never authority.

`execution/task-packets.js#prepareTaskExecution` maps thrown adapter failures to fixed `ADAPTER_ERROR`; v2 `runCycle` also catches invocation errors without persisting arbitrary causes. Canonical outcome handling rechecks generation/attempt before building uncertainty. Legitimate task inputs and successful adapter result summaries are application data, not automatically redacted; this pass tests **error-message** secrecy, not a generic payload-redaction service. The trusted SDK still has legacy message-only TypeErrors (for example `packets must be an array`) and actor transport can expose a raw local channel error to its host. No frozen public code, wire shape, persisted record, CoordinationError classification or optional v1 status is normalized away.

### Narrow diagnostic change and compatibility

Prior v1 startup catch bypassed sanitizer logging; both prior sanitization-stage loggers lacked operation provenance and copied native string `code`/`syscall` values. New instrumentation records the failing native call **before** cleanup or translation. `CHORD_STORAGE_DIAGNOSTICS=1` is explicit host-process opt-in, never actor/payload-controlled. Output is stderr only:

```text
chord.storage.diagnostic {"operation":"sqlite.begin","errcode":5,"errno":null}
```

Fixed operation allowlist: `fs.lstat`, `fs.open`, `fs.close`, `sqlite.open`, `sqlite.close`, `sqlite.prepare`, `sqlite.exec`, `sqlite.all`, `sqlite.get`, `sqlite.run`, `sqlite.quick_check`, `sqlite.begin`, `sqlite.commit`, `sqlite.rollback`. The generic method labels deliberately omit statement contents. Only own numeric data-descriptor `errcode`/`errno` values or null are emitted—no message, code/syscall strings, SQL, file path, bind payload or credential. Accessors are not evaluated; descriptor extraction, serialization and synchronous stderr fd writes are guarded. A failed diagnostic rethrows the identical native exception. Synchronous fd writes avoid an asynchronously queued stream error outside that guard and add no host callback/hook to transactions. No schema/state/effect/timeout/retry change.

Diagnostic lines record **native call failures**, including handled ENOENT during normal create and best-effort cleanup ROLLBACK outside a transaction. Read chronologically: later retirement errors are not the initial startup failure. No line is guaranteed when diagnostics are disabled, the sink fails, or a failure is pure contract validation. Instrumentation is not a public API, durable evidence ledger or certification facility.
